### Summary of Fix

#### Root Cause
When parsing field lists formatted like `:param <type> <name>:`, Sphinx's `DocFieldTransformer` in [`sphinx/util/docfields.py`](file:///E:/RofU/Supreme/carb_workspaces/sphinx-doc__sphinx-9230/sphinx/util/docfields.py#L301) was using `fieldarg.split(None, 1)`, which splits on the **first** space character. 

For complex types containing internal spaces (e.g., `dict(str, str)`, `Union[int, str]`, `Tuple[int, str]`), `fieldarg` (e.g., `"dict(str, str) opc_meta"`) was split into:
- **Type**: `"dict(str,"`
- **Parameter Name**: `"str) opc_meta"`

This resulted in incorrect HTML rendering such as `str) opc_meta (dict(str,) –(optional)`.

#### Resolution
1. **Surgical Code Edit**: Updated `DocFieldTransformer.transform` in [`sphinx/util/docfields.py`](file:///E:/RofU/Supreme/carb_workspaces/sphinx-doc__sphinx-9230/sphinx/util/docfields.py#L301) to use `fieldarg.rsplit(None, 1)` instead of `split(None, 1)`. Splitting from the right correctly separates the parameter name (the final token) from complex type expressions containing spaces, brackets, or commas.
2. **Added Unit Test**: Created `test_info_field_list_with_complex_type` in [`tests/test_domain_py.py`](file:///E:/RofU/Supreme/carb_workspaces/sphinx-doc__sphinx-9230/tests/test_domain_py.py#L987) to verify that docfields containing `:param dict(str, str) opc_meta:` and `:param Union[int, str] id_val:` render correctly.
3. **Verification**: Executed the test suite using `pytest`. All 46 tests in `test_domain_py.py` and 555 tests in related test suites passed cleanly with 0 failures.
