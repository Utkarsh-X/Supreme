### Approach & Algorithm

1. **Key Mathematical Property**:
   In a strictly increasing subsequence, if the tail (maximum) element is $\le X$, then every element in the subsequence is guaranteed to be $\le X$.
   Therefore, for a prefix $(A_1, A_2, \dots, A_R)$, the maximum length of a strictly increasing subsequence consisting only of elements $\le X$ is equivalent to finding the maximum length $k$ such that the minimum ending element of an increasing subsequence of length $k$ is $\le X$.

2. **Standard LIS Array**:
   We process the elements $A_1, A_2, \dots, A_N$ incrementally from $1$ to $N$ while maintaining the dynamic programming array $dp$, where $dp[k-1]$ stores the minimum tail element of a strictly increasing subsequence of length $k$.
   The $dp$ array is always strictly increasing.

3. **Offline Query Processing**:
   We store all queries grouped by prefix index $R_i$.
   As we iterate $r$ from $1$ to $N$:
   - We update $dp$ with element $A_r$ using binary search (`bisect_left`).
   - For each query $(R_i = r, X_i)$, we binary search on the current $dp$ array using `bisect_right(dp, X_i)` to find the largest $k$ such that $dp[k-1] \le X_i$.

4. **Complexity**:
   - **Time Complexity**: $\mathcal{O}((N + Q) \log N)$, easily executing well under 0.4 seconds for $N, Q = 200{,}000$.
   - **Space Complexity**: $\mathcal{O}(N + Q)$.
