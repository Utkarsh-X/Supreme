### Method Explanation

1. **Layer-by-Layer Row Clearance**:
   - In any column $c$, blocks maintain their relative vertical ordering. We sort the blocks in column $c$ by their initial $Y$-coordinate. Let $B_{c, m}$ be the $m$-th lowest block in column $c$ (1-indexed).
   - For a row clearance to occur, every column $c \in \{1, \dots, W\}$ must have a block at row 1.
   - The maximum number of row clearances that can ever happen is $K = \min_{1 \le c \le W} (\text{number of blocks in column } c)$. If any column has 0 blocks ($K = 0$), no row clearances ever occur.

2. **Clearance Times Recurrence**:
   - The $m$-th row clearance removes $B_{1, m}, B_{2, m}, \dots, B_{W, m}$ simultaneously.
   - Let $T_{clear, m}$ be the time step at which the $m$-th row clearance takes place:
     $$T_{clear, 0} = 0$$
     $$T_{clear, m} = \max\left(T_{clear, m-1} + 1, \max_{1 \le c \le W} Y(B_{c, m})\right)$$
   - Explanation: $B_{c, m}$ cannot reach row 1 before $T_{clear, m-1}$ (since $B_{c, m-1}$ occupies row 1 until time $T_{clear, m-1}$), and requires $Y(B_{c, m}) - 1$ steps of falling time to reach row 1.

3. **Answering Queries**:
   - For a query asking about block $A_j$ at time $T_j + 0.5$:
     - Find the column and rank $m$ (1-indexed) of block $A_j$.
     - If $m > K$, block $A_j$ is never removed, so the answer is `Yes`.
     - Otherwise, if $T_j < T_{clear, m}$, block $A_j$ has not been removed yet by time $T_j + 0.5$, so the answer is `Yes`.
     - If $T_j \ge T_{clear, m}$, block $A_j$ was removed at or before time $T_{clear, m}$, so the answer is `No`.

### Complexity
- **Time Complexity**: $\mathcal{O}(N \log N + Q)$ for sorting blocks by height in each column and answering queries in $\mathcal{O}(1)$ time.
- **Space Complexity**: $\mathcal{O}(N + Q)$ to store block positions and query results.
