I have fixed the issue where extra leading and trailing whitespace was inserted into inline code highlighting in LaTeX PDF output.

### Root Cause
When Pygments highlights code using `LatexFormatter`, it wraps the highlighted tokens in a `Verbatim` block (`\begin{Verbatim}[commandchars=\\\{\}]\n...\n\end{Verbatim}\n`). When translating inline code (`literal` node with `:code:` or a language role), `LaTeXTranslator.visit_literal` replaced `\begin{Verbatim}...` with `\sphinxcode{\sphinxupquote{` and stripped `\end{Verbatim}`. However, the leading newline after `\begin{Verbatim}` and the trailing newline before `\end{Verbatim}` remained inside `\sphinxcode{\sphinxupquote{...}}`. In LaTeX, newlines inside macro arguments are rendered as space characters, producing unwanted leading and trailing spaces around the inline code in PDF output.

### Fix
1. Modified `visit_literal` in [sphinx/writers/latex.py](file:///E:/RofU/Supreme/carb_workspaces/sphinx-doc__sphinx-10435/sphinx/writers/latex.py#L1707-L1717) to strip the `Verbatim` environment wrapper and any leading/trailing newlines (`\r\n`) around the highlighted content before emitting `\sphinxcode{\sphinxupquote{<content>}}`.
2. Updated test assertion in [tests/test_build_latex.py](file:///E:/RofU/Supreme/carb_workspaces/sphinx-doc__sphinx-10435/tests/test_build_latex.py#L1647) to verify that inline code in LaTeX output does not contain leading or trailing newlines inside `\sphinxcode{\sphinxupquote{...}}`.
