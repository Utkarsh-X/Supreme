I have fixed the issue where `floatformat('0.00', 0)` and `floatformat(Decimal('0.00'), 0)` raised `ValueError: valid range for prec is [1, MAX_PREC]`.

### Cause of the Issue
When `floatformat` rounded `Decimal` numbers using `d.quantize(...)`, it created a temporary `decimal.Context(prec=prec)` to prevent `InvalidOperation` exceptions when local context precision was low (#15789).
However, `units` was calculated as `len(tupl[1]) + tupl[2]` whenever `m = int(d) - d` was zero. For inputs like `Decimal('0.00')`, `tupl.digits` has a length of `1` (`(0,)`) and exponent `-2`, which resulted in `units = 1 + (-2) = -1`. When formatting with 0 decimal places (`p = 0`), this computed `prec = 0 + (-1) + 1 = 0`. Passing `prec=0` to `decimal.Context` raised `ValueError`.

### Fix
In [`django/template/defaultfilters.py`](file:///E:/RofU/Supreme/carb_workspaces/django__django-16485/django/template/defaultfilters.py#L181-L185), `units` is now simplified to `len(tupl[1]) + abs(tupl[2])`, ensuring `units` and `prec` are always strictly positive integers for all `Decimal` inputs.

Unit tests have been added to [`tests/template_tests/filter_tests/test_floatformat.py`](file:///E:/RofU/Supreme/carb_workspaces/django__django-16485/tests/template_tests/filter_tests/test_floatformat.py#L111-L115) covering string and `Decimal` inputs of `"0.00"` with 0 decimal places.
