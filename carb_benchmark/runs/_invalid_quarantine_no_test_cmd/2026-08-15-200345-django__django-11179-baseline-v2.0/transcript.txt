I have fixed the issue where calling `.delete()` on a model instance without dependencies (which triggers the fast-delete path) did not clear its primary key.

### Root Cause
In [`django/db/models/deletion.py`](file:///E:/RofU/Supreme/carb_workspaces/django__django-11179/django/db/models/deletion.py#L275-L281), `Collector.delete()` optimized for the single-instance fast-delete case by performing a batch delete and immediately returning the deleted count dictionary. However, unlike the general deletion path, it omitted resetting the instance's primary key attribute to `None` before returning.

### Changes Made
1. **[`django/db/models/deletion.py`](file:///E:/RofU/Supreme/carb_workspaces/django__django-11179/django/db/models/deletion.py#L280)**: Added `setattr(instance, model._meta.pk.attname, None)` right after executing `sql.DeleteQuery(model).delete_batch([instance.pk], self.using)` in the fast-delete branch.
2. **[`tests/delete/tests.py`](file:///E:/RofU/Supreme/carb_workspaces/django__django-11179/tests/delete/tests.py#L526)**: Added `test_fast_delete_instance_set_pk_none` to verify that deleting an instance of a dependency-free model correctly sets its `pk` attribute to `None`.
