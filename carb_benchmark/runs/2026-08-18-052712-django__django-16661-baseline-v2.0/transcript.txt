I have fixed the issue where `ModelAdmin.lookup_allowed()` incorrectly raises `DisallowedModelAdminLookup` when traversing lookups across models that use a Foreign Key / One-to-One Key as their primary key.

### Root Cause
When building `relation_parts` in `ModelAdmin.lookup_allowed()`, intermediate lookup parts were skipped if `field` matched `prev_field.path_infos[-1].target_fields`. For models where the primary key is a relational field (such as a `OneToOneField(..., primary_key=True)`), that relational field was skipped in `relation_parts`. If the lookup then continued to deeper relations (e.g. `restaurant__place__country`), skipping `place` caused `country` to be appended directly onto `restaurant` (`restaurant__country`), stripping `place` from the lookup path and causing `lookup_allowed()` to fail.

### Solution
Updated [django/contrib/admin/options.py](file:///E:/RofU/Supreme/carb_workspaces/django__django-16661/django/contrib/admin/options.py#L454-L486) so that if a target field was skipped because it matched `prev_field.target_fields`, but a subsequent lookup part extends beyond it to a non-target field on the referenced model, the skipped intermediate relational field is retained in `relation_parts`.
