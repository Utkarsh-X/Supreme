I have resolved the issue where inline code highlighting added extra whitespace at the start and end of inline code in LaTeX/PDF output.

### Cause
When rendering highlighted inline code in LaTeX mode (`visit_literal`), Pygments' block formatter output was previously converted to `\sphinxcode{\sphinxupquote{...}}` with newlines inserted directly after `\sphinxupquote{` and before `}}`. In LaTeX/TeX, a newline after an open brace or before a close brace is interpreted as a space token in horizontal text mode, resulting in leading and trailing space characters around inline code in the PDF.

### Solution
1. **LaTeX Writer ([`sphinx/writers/latex.py`](file:///E:/RofU/Supreme/carb_workspaces/sphinx-doc__sphinx-10435/sphinx/writers/latex.py#L1706-L1716))**:
   - Passed `nowrap=True` to `self.highlighter.highlight_block(...)` (matching HTML writers).
   - Removed leading and trailing newlines from the Pygments output before wrapping in `\sphinxcode{\sphinxupquote{...}}`.

2. **Tests ([`tests/test_build_latex.py`](file:///E:/RofU/Supreme/carb_workspaces/sphinx-doc__sphinx-10435/tests/test_build_latex.py#L1607-L1628))**:
   - Updated `test_latex_code_role` to assert that highlighted inline code is placed directly inside `\sphinxcode{\sphinxupquote{...}}` without extra newlines, eliminating unwanted whitespace in PDF rendering.
