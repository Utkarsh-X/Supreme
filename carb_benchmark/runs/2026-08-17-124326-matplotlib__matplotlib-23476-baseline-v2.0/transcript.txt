### Root Cause
When a figure is displayed on HiDPI/Retina screens (e.g., MacOSX backend on M1 Mac, or Qt/GTK backends with HiDPI), `_set_device_pixel_ratio` scales the physical figure resolution `figure.dpi` by multiplying `figure._original_dpi` by `device_pixel_ratio` (e.g., $100 \times 2 = 200$).

When unpickling a figure, `figure._original_dpi` ($100$) and `figure.dpi` ($200$) were restored from the pickled state. However, `FigureCanvasBase.__init__` unconditionally ran `figure._original_dpi = figure.dpi`, overwriting `_original_dpi` with the already-scaled DPI ($200$). When the backend canvas manager re-initialized and called `_set_device_pixel_ratio(2)`, it recalculated `dpi = ratio * figure._original_dpi = 2 \times 200 = 400`. Unpickling repeatedly doubled the figure's DPI ($200 \to 400 \to 800 \to \dots$) until an `OverflowError` occurred.

### Fix
1. Updated [`FigureCanvasBase.__init__`](file:///E:/RofU/Supreme/carb_workspaces/matplotlib__matplotlib-23476/lib/matplotlib/backend_bases.py#L1653-L1660) to check if `figure._original_dpi` is already defined on the figure before assigning it. 2. Updated [`_set_device_pixel_ratio`](file:///E:/RofU/Supreme/carb_workspaces/matplotlib__matplotlib-23476/lib/matplotlib/backend_bases.py#L2102-L2110) to update `self._device_pixel_ratio` before calling `_set_dpi`.

### Summary of Bug & Resolution

#### Bug Cause
When a figure is rendered on HiDPI / Retina displays (such as MacOSX backend on M1 Mac or Qt/GTK with `device_pixel_ratio > 1`), Matplotlib scales `figure.dpi` by multiplying `figure._original_dpi` by `device_pixel_ratio` (e.g. $100 \times 2 = 200$).

When unpickling a figure:
1. Both `_original_dpi` ($100$) and `dpi` ($200$) are restored onto the figure object.
2. `FigureCanvasBase.__init__` was unconditionally running `figure._original_dpi = figure.dpi`, overwriting `_original_dpi` with the scaled DPI ($200$).
3. When the backend canvas manager attached to the window and called `_set_device_pixel_ratio(2)`, it computed `dpi = ratio * figure._original_dpi = 2 \times 200 = 400`.
4. Repeating this in a loop doubled the DPI exponentially ($200 \to 400 \to 800 \to 1600 \dots$) until an `OverflowError` occurred in the backend.

#### Solution
- Modified [`FigureCanvasBase.__init__`](file:///E:/RofU/Supreme/carb_workspaces/matplotlib__matplotlib-23476/lib/matplotlib/backend_bases.py#L1653-L1660) to check if `figure._original_dpi` already exists. If it does, `_original_dpi` is preserved and `figure.dpi` is reset to `_original_dpi` for the default canvas ratio ($1$).
- Modified [`_set_device_pixel_ratio`](file:///E:/RofU/Supreme/carb_workspaces/matplotlib__matplotlib-23476/lib/matplotlib/backend_bases.py#L2102-L2110) to update `self._device_pixel_ratio` before triggering `_set_dpi`.
- Updated [`Figure._set_dpi`](file:///E:/RofU/Supreme/carb_workspaces/matplotlib__matplotlib-23476/lib/matplotlib/figure.py#L2590-L2595) to ensure `_original_dpi` stays synced when `_set_dpi` is called.
- Added unit test `test_unpickle_with_device_pixel_ratio` in [`test_figure.py`](file:///E:/RofU/Supreme/carb_workspaces/matplotlib__matplotlib-23476/lib/matplotlib/tests/test_figure.py#L1384-L1395) to verify unpickling across multiple iterations under HiDPI pixel ratios.
