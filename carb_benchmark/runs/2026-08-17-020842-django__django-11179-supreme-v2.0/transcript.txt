### Root Cause Analysis
In [Collector.delete()](file:///E:/RofU/Supreme/carb_workspaces/django__django-11179/django/db/models/deletion.py#L274-L281), an optimization exists for single model instances with no dependencies (`can_fast_delete`). While the standard path set `setattr(instance, model._meta.pk.attname, None)` on deleted instances before returning, the fast-delete branch returned early after running the batch SQL delete query without updating the model instance's primary key attribute to `None`.

---

### Solution
1. **Fix in `Collector.delete()`**: Added `setattr(instance, model._meta.pk.attname, None)` in [django/db/models/deletion.py](file:///E:/RofU/Supreme/carb_workspaces/django__django-11179/django/db/models/deletion.py#L280) on the fast-delete branch before returning.
2. **Regression Test**: Added `test_fast_delete_instance_set_pk_none` to `FastDeleteTests` in [tests/delete/tests.py](file:///E:/RofU/Supreme/carb_workspaces/django__django-11179/tests/delete/tests.py#L526) to verify that `instance.pk` is set to `None` when calling `.delete()` on an instance with no dependencies.
