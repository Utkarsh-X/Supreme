I have investigated and resolved the issue with `is_zero` evaluating incorrectly on expressions involving complex numbers in `Add`.

### Cause of the Issue
In `sympy/core/add.py`, `Add._eval_is_zero()` previously checked if any terms in `Add` were imaginary (`im = True`), and if so, returned `False` whenever the real part summed to zero (`b.is_zero is True`). It assumed that imaginary terms in an `Add` can never sum to zero. However, expressions with multiple imaginary terms (e.g. `e = -2*I + (1 + I)**2`) can have imaginary parts that sum to zero, making `return False` incorrect.

### Fix
Updated `Add._eval_is_zero` in [`sympy/core/add.py`](file:///E:/RofU/Supreme/carb_workspaces/sympy__sympy-15875/sympy/core/add.py#L532-L567) to collect imaginary terms (`im_I`) multiplied by `I` (converting them to real terms) and check `b_im.is_zero` on their sum (`b_im = Add(*im_I)`):
- If `b.is_zero` is `True` (real part is 0) and `im_I` is non-empty, `_eval_is_zero` now evaluates and returns `b_im.is_zero`.
- Added test coverage in [`sympy/core/tests/test_arit.py`](file:///E:/RofU/Supreme/carb_workspaces/sympy__sympy-15875/sympy/core/tests/test_arit.py#L1985-L1992).

     - If `im_I` is empty, returns `True`.
     - Otherwise, computes `b_im = self.func(*im_I)` and returns `b_im.is_zero` (returning `None` if unresolvable, or `True`/`False` when determined).
